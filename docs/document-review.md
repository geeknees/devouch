## 修正した食い違い

| 箇所 | 問題 | 修正 |
|---|---|---|
| ハンドオフの公開位置取得 | 証拠を復元できない場合を一律 `unavailable` と読め、CLI の未公開 `missing` と区別できなかった | 必要範囲を照会して公開がない場合と、照会自体を完了できない場合を区別 |
| `publication.json` | CLI では任意の補助情報だが、ハンドオフでは Action が必ず一時生成するように記載 | 公開位置は CLI が再構成し、補助ファイルの作成・引き渡しは任意に統一 |
| デモの順序 | 失効後に初めて Action を動かす順序で、有効時と失効後を比較できなかった | 有効時の実 fork PR → 失効 → 同じ JSON で Action 再実行、の順に統一 |
| 対象人数と送信名義 | 「一人の対象・一つの推薦」と、管理者・エージェント両名義の確認が併記され、同時保持の制約との関係が不明だった | 同時に一件と明記。片方の発行・PR・失効後、もう片方へ新規発行して順番に確認する計画へ整理 |
| 旧版 README の例 | `init` は推薦者2名・必要数2、直後の YAML は1名・必要数1。委任の期限例も過去だった | 2名・必要数2に統一し、推薦を二人から得る前提、base 側への設定反映、未来の期限への置換を記載 |
| 旧版 README の CI | required check の設定だけで検証を強制できるように読め、fork に渡らない RPC secret の制限も不明だった | PR が workflow を変更できる境界と、生成済み workflow の fork 制約を記載。実際の CI は変更していない |
| 文書間の参照 | Hono-kun の説明が既存版の機能か不明瞭で、企画の成果物一覧には CLI 設計の追記がなかった | 既存版・将来例を明記し、CLI 設計と本レビューへの参照を追加 |

旧版 workflow の境界は [GitHub の公式説明](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target)と照合した。新しい推薦版の Action は引き続き結果表示用であり、強制的なマージ制御を実装したという変更ではない。

## 設計判断が残る点

### 1. 複数推薦の同時保持

管理者とエージェントのアカウントを順番に試すことと、両方を日常的に同時利用できることは異なる。現在の一記録・一キーの構成では、別の推薦を公開すると前の推薦が失効する。一般の OSS へ導入する前に公開先の分け方が必要であり、Git の JSON を増やすだけでは解決しない。

今回は一件ずつ試すデモ手順を明確にした。複数保持の方式や追加コントラクトの採用は決めていない。

### 2. ENS の検証契約

「未知のリンク・upgrade を通さない」という要件に対し、具体的な履歴確認方法は未確定である。現在値と `TextUpdated` だけを確認しても、途中で変更され元に戻った record のリンクや実装まで追跡できたとは言えない。ENS がリンク変更と proxy upgrade を提供することは [公式仕様](https://docs.ens.domains/ensv2/permissioned-resolver/)で確認した。

さらに、`allowedResolvers` にない公開先と未対応の実装を、方針の不採用・不正・検証不能のどれに分類するかが確定していない。署名型・名前の正規化・時刻の判定・ID の再利用範囲・一部操作のエラー JSON も、[CLI の未確定の検証契約](cli-interface.md#未確定の検証契約)に集約した。これらは実装時に暗黙のルールを作らず、期待する結果を先に定める必要がある。

### 3. 導入と8時間枠の実現性

認証不要 RPC から必要な履歴を時間内に取得できること、ENS の初期化・実ガス、ランタイムを内包した Action、設定例の配布、第三者の導入は未検証である。両送信名義と失効後の再実行を含む8時間の見積もりも未測定。「メンテナーは2ファイル」という手順だけで導入の容易さを実証したとは扱わない。

## 維持した方針

推薦の発行・失効・再利用を中心とし、運営者の必須バックエンドや共通鍵を置かない。ENS に本文と署名を公開し、`.devouch/` に通常の JSON と repo 方針を置く。推薦対象は実際の PR 作者の GitHub 数値 ID。World は条件付きで、人間性・管理者との関係・コード品質を推薦だけで証明したとは表示しない。初期草案と参考シナリオは、その位置づけを保って残した。

今回の変更は文書だけである。実装、依存関係、workflow、コントラクトへの変更や外部への公開・取引は行っていない。
